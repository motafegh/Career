The project grew across Python, data, machine learning, agents, graph-related work, blockchain, and zero-knowledge machine learning areas. It involved real data acquisition, repeated model training, dataset-quality problems, Linux use, and a large multi-module repository.

## 3. Central lesson

Sentinel demonstrates both the value and risk of ambitious AI-assisted projects.

What worked:

- one persistent mission;
- visible system growth;
- real inputs and failures;
- technically meaningful questions;
- repeated opportunities to learn during construction.

What failed structurally:

```text
ambitious mission
→ interesting technical possibility
→ new module or ecosystem
→ AI-assisted architecture growth
→ additional integration surfaces
→ ownership and verification lag
```

The correct lesson is:

> Preserve a mission large enough to create curiosity, while keeping the active product boundary narrow enough for Ali to understand, test, diagnose, and own.

## 4. Assistance and ownership boundary

The repository was built with extensive AI-assistant help.

Ali has stated that he can explain much of the source when reviewing it, but he does not claim the ability to recreate the project from a blank repository independently.

Therefore Sentinel establishes:

- exposure;
- guided understanding of selected parts;
- project-direction and persistence evidence;
- selected operational and experimental experience.

It does not establish broad independent ownership of the complete architecture, ML system, data system, graph work, agents, blockchain, or zkML components.
