# Career Project Areas

**Purpose:** Career-side project-specific records and future project-specific career artifacts.

This directory gives each portfolio project its own bounded Career area without moving technical project operation into the Career repository.

## Current project areas

- [`upgradepilot/`](upgradepilot/) — active primary flagship and main current capability-building vehicle.
- [`sentinel/`](sentinel/) — historical evidence with AI-maintained portfolio rehabilitation outside the active Career learning allocation.
- [`aegislab/`](aegislab/) — historical security-learning and project-design evidence.

JobHunter is not stored here because Career classifies it as market-intelligence/support infrastructure. Its Career-side area is [`../../market/jobhunter/`](../../market/jobhunter/).

## What belongs in a project area

A project area may hold Career-level material such as:

- the canonical Career record for that project;
- Ali-versus-AI ownership conclusions;
- capability evidence or reassessment conclusions specific to the project;
- portfolio/CV positioning and claim limits;
- Career decisions about reuse, rehabilitation, reactivation, or stopping;
- project-specific review findings that materially affect Career decisions.

Create additional files only when a real Career need appears. Do not create placeholder trackers or duplicate information merely because a folder exists.

## What does not belong here

Technical truth and continuation remain in the project repository. Do not duplicate:

- live technical state or exact next implementation action;
- source code or tests;
- technical plans, milestones, ADRs, specifications, working memory, or experiments;
- project-local commands, logs, generated evidence, or implementation trackers.

Career may inspect those sources and record the resulting **career-level conclusion** here.

## Common evidence split

When relevant, project records should keep these concepts separate:

```text
Repository capability
→ what the current project demonstrably does

Ali evidence
→ what Ali can personally understand, explain, modify, test, diagnose, or direct

AI contribution
→ what substantive architecture, code, testing, analysis, or continuation was AI-generated or AI-operated

Career claim
→ what Career may honestly state externally

Non-claim
→ what repository sophistication does not establish about Ali
```

Project completion, repository size, passing tests, or AI-generated implementation do not by themselves establish Ali capability.
