## C4 — Project portfolio and admission system

**State:** COMPLETE

### C4.1 Strong current model

The **substantive admission model is strong** and already implements the restraint we discussed after P0–P7:

- one primary flagship by default;
- supporting work requires one named gap, bounded scope/time, explicit stop/completion condition, and evidence that the flagship cannot address the gap proportionately;
- project admission checks whether a smaller exercise/contribution/increment is sufficient before authorizing another project;
- experiments require a question, cost ceiling and explicit admit/defer/reject outcome;
- technology names cannot be the mission;
- historical project size is not a reason to reactivate;
- current AI-full project assets can carry portfolio value without becoming Ali capability evidence;
- small exercises do not automatically become projects.

This means the current policy already supports the recent conclusion:

> do not create new full projects merely to practice P0–P7; use UpgradePilot as the flagship and admit only the smallest bounded supporting vehicle when a real gap cannot be covered proportionately.

### C4.2 Current project records are mutually consistent

The canonical current portfolio and project records agree on:

- **UpgradePilot** — sole primary capability-building flagship;
- **JobHunter** — active AI-full applied-AI product + Career market-intelligence infrastructure + portfolio asset, low-overhead and not a learning flagship;
- **Sentinel** — active AI-full ML/data/security research asset + portfolio case-study source, no ordinary learning allocation;
- **AegisLab** — historical evidence, inactive.

The project records correctly separate repository capability, Ali evidence, AI contribution, Career claims and non-claims.

### C4-F01 — Portfolio selection policy improperly embeds stale current allocation

**CLASS:** CONFLICT + STALE  
**SEVERITY:** HIGH  
**CONFIDENCE:** HIGH  
**OWNER:** `strategy/PROJECT_PORTFOLIO_AND_SELECTION_POLICY.md` §3

The durable policy contains a **Current portfolio allocation** section that says:

- UpgradePilot = Primary;
- Sentinel = Historical evidence;
- AegisLab = Historical evidence;
- no other major project authorized.

It omits JobHunter and directly conflicts with the current canonical portfolio/project records, where JobHunter and Sentinel are active AI-full assets.

This is more than an outdated row. Root truth routing assigns **current project roles** to `portfolio/PROJECT_PORTFOLIO.md`, while the selection policy owns role taxonomy/admission/retirement rules.

**WHY IT MATTERS**

The policy is higher in the generic authority chain and can cause a fresh agent to incorrectly deactivate Sentinel/JobHunter or mis-handle a new-project decision.

**PROVISIONAL DISPOSITION:** **MOVE / REMOVE** the current-allocation section from the durable policy and link to `portfolio/PROJECT_PORTFOLIO.md` for current roles. Do not merely refresh the table, because that recreates the same drift mechanism.

**COUNTEREVIDENCE:** the rest of the policy is strong and current; only the embedded live/current allocation is defective.
