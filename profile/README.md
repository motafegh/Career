# Profile Area

This area contains durable public-safe personal and professional context used by Career.

The profile area deliberately separates **concise canonical facts** from **detailed supporting context**. Neither profile file owns technical capability depth, live Career state, role strategy, or project status.

## Files and authority

### `CAREER_PROFILE.md` — canonical concise profile summary

Use as the normal owner for stable public-safe profile facts and durable profile-level conclusions, including:

- current professional situation;
- concise professional-history shape;
- education facts at the verified level;
- language / durable work-preference facts;
- broad technical exposure;
- stable learning / AI-use preferences;
- durable strengths / risks / non-claims;
- high-level unresolved profile items.

This is the default profile source for governance and ordinary Career orientation.

It should remain concise enough that agents do not need to reread a full biography for every Career operation.

### `COMPREHENSIVE_PERSONAL_AND_PROFESSIONAL_PROFILE.md` — detailed supporting context

Use when a decision materially depends on deeper personal/professional context, such as:

- detailed education / thesis context;
- three-business professional history;
- management / executive / operational responsibility;
- people, asset, purchasing, sales, or difficult-decision experience;
- communication across hierarchy / expertise levels;
- investigation / anomaly-following patterns;
- technical origin and progression;
- AI-assisted engineering style;
- learning / motivation / execution patterns;
- career / work preferences;
- unresolved personal/professional questions.

This file is a **detailed supporting record**, not a second competing canonical owner of capability, strategy, or live state.

When the comprehensive file contains a detail that is later promoted to a stable Career fact, reconcile the concise `CAREER_PROFILE.md` rather than letting contradictory summaries persist.

## Evidence interpretation

Profile content may use several evidence classes. Do not treat them as interchangeable.

### Stable public-safe fact

Directly stated and sufficiently stable to use in Career reasoning, for example verified degree/field or prior formal role.

### Professional-history context

Reported prior responsibility or circumstance useful for role fit / positioning. It may be truthful and important without constituting technical capability evidence.

### Preserved evidence

Supported by inspectable project, repository, work, or assessment evidence.

### Self-reported / observed working pattern

A repeated or explicitly reported tendency such as situational management, investigative persistence, or work-mode flexibility. Useful for hypotheses and role fit, but not automatically a professional capability claim.

### Working interpretation

A cautious Career inference drawn from several facts/patterns. Must remain revisable.

### Unresolved / unassessed

Insufficiently reconstructed or tested. `Unresolved` does not mean false or incapable.

## Core three-axis profile model

Where useful, Career should reason about three separate dimensions:

```text
PROFESSIONAL MATURITY
→ prior responsibility, people, operations, ambiguity, stakeholders, assets, decisions

TECHNICAL CONTEXT
→ education, ML thesis, technical exposure, projects, AI-assisted engineering context

TECHNICAL OWNERSHIP
→ only what current capability evidence shows can be understood, modified, tested, diagnosed, transferred, and defended
```

Do not collapse these dimensions into one vague seniority/skill judgment.

A person may have high professional maturity, broad technical context, and still-developing software-engineering ownership at the same time.

## Routing rule

Use the **smallest sufficient source**:

```text
ordinary stable profile fact
→ CAREER_PROFILE.md

decision depends on deeper biography / responsibility / preference context
→ CAREER_PROFILE.md + relevant part of COMPREHENSIVE_PERSONAL_AND_PROFESSIONAL_PROFILE.md

what can actually be performed / owned technically
→ CAPABILITY_EVIDENCE_LEDGER.md + underlying evidence when needed

what is true right now / what Career does next
→ CAREER_STATE.md
```

Biography may inform role fit, positioning, and hypotheses. It may **not** override technical capability evidence.

## Public-safety rule

Keep the profile professionally useful without publishing unnecessary sensitive context.

Public-safe education, professional titles, generalized work history, languages, responsibilities, and preferences may be recorded when useful.

Do not publish unnecessary:

- private family identities;
- private financial details;
- authentication secrets / credentials;
- addresses / phone numbers / private contact details;
- medical details;
- private legal matters;
- confidential employer/application correspondence;
- private routines with no Career need.

## Maintenance

Update the concise profile when a stable fact or durable profile conclusion changes.

Update the comprehensive profile when deeper reconstructed history, durable preferences, or meaningful personal/professional context becomes available.

Do not update either file after ordinary technical project progress unless that progress produces a durable profile-level conclusion. Technical capability changes belong in the Capability Ledger.
