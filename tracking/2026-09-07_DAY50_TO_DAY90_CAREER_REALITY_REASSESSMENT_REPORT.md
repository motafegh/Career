## A0.3 Why the original roadmap was replaced

### Fact / observation

On 2026-07-23, only a few days into execution, UpgradePilot explicitly replaced the original milestone decomposition with an evidence-derived learning/building route.

The replacement recorded that real cases S001–S003 showed the first credible executable core could not safely treat repository context, baseline comparison, acquisition, persistence, failure behavior, and related evidence responsibilities as clean later additions after a simple early report slice.

The replacement established evidence gates and the route that evolved into the current:

```text
D0 → D1 → B1 → B2 → B3 → B4 → B5 → X1 → C1
```

The current route explicitly says stages are evidence gates rather than fixed calendar promises.

### Interpretation

The original calendar was not merely missed; an important part of its sequencing model was rejected by early project evidence.

This is a legitimate engineering correction, not automatically a planning failure.

However, evidence-gated routing does not remove the Career-level Day-60/Day-90 time constraint.

### Ali-specific consequence

Two lenses must be preserved simultaneously:

1. **calendar pace:** are we using the finite 90-day Career period effectively?
2. **evidence-gate integrity:** are technical stages advancing only when the real product evidence justifies them?

Using only the first would punish legitimate engineering correction. Using only the second could allow the Career outcome to drift indefinitely.

### Decision / proposal

Judge the remaining 40 days with both clocks.

### Unresolved

Whether some later complexity was necessary evidence-driven thickening or avoidable overinvestment remains to be assessed.
